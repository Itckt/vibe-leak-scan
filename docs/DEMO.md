# 三分鐘作品示範講稿

這是一份可照著操作的預備講稿，時間是編排目標，未實測整段演示耗時。示範只使用本機 fixture；開始前先確認頁面能開啟，並預留時間處理連接埠問題。

## 開場前準備

依[示範啟動步驟](SHOWCASE.md)開啟掃描器與 fixture。預設示範位址是 `http://127.0.0.1:4300` 與 `http://127.0.0.1:4174`；需要依賴安裝時，先完成[使用指南](USAGE.md)，不要把安裝時間算入示範。

準備三個可快速切換的畫面：掃描器首頁、本文件，以及[安全測試導覽](TEST-TOUR.md)。若現場環境無法啟動，改用[先前實拍截圖](SHOWCASE.md)，並明說這是既有本機示範紀錄。

等待掃描時先講檢查範圍，結果未出現就不要口頭宣告成功。若需要縮短演示，保留覆蓋範圍、遮蓋證據與一項修復指令，技術細節留待追問。

## 現場應該核對的訊號

- 報告目標是本機 fixture，外部程式檔為三個，其中兩個經匯入或預載發現。
- `assets/chunk.js` 與 `assets/nested.js` 各自有對應的假密鑰發現；畫面只顯示遮蓋後內容。
- 工具切為程式碼代理後，指令包含搜尋 codebase、伺服器路由及建置輸出驗收。
- 私密密鑰卡片的複製按鈕上方有手動撤銷提示。
- 複製整份計劃若失敗，頁面顯示可選取文字；示範不必要求系統剪貼簿權限。

## 常見追問的簡短回答

**為甚麼不直接把網站跑起來掃？** 目前範圍是有限的靜態分析，不執行不受信任的目標程式。代價是部分執行時載入無法還原，因此需要清楚說明覆蓋限制。

**密鑰一定還有效嗎？** 工具辨識格式及部分語意，例如 JWT 角色，不拿密鑰向供應商測試有效性。報告會說明疑似憑證及建議處理方式。

**如何證明深度掃描不能繞過？** 展示[未驗證 API 請求測試](../tests/integration.test.js)：它要求 403，並斷言目標 fixture 沒有收到任何請求。

**這是你一個人手寫的嗎？** 這是 AI 協作開發的作品。說明自己實際參與的需求、檢查、取捨與驗收；展示能解釋及重現的證據，不把 AI 產出的全部程式碼描述成獨立手寫。

## 收尾

示範後以 `Ctrl+C` 關閉自己啟動的兩個程序，移除該終端的測試環境變數。需要離線分享時使用專案內的圖片，不複製 data/ 報告或 fixture 的原始回應。
